GitHub PagesとSupabaseの初期設定

HTMLを公開するGitHubと、データを保存するSupabaseを接続します。登録された利用者だけが備品を確認・更新できます。

このサイトの接続設定は完了しています。Supabase「管理システム」には保存用テーブル・更新関数を作成済みです。このプロジェクトではsetup.sqlを再実行せず、「3. 利用者を登録する」から進めてください。以下の全手順は、新しいプロジェクトに複製する場合の案内です。

1. Supabaseの保存先を作る

Supabaseの管理画面にログインし、この備品管理用の新しいプロジェクトを作ります。名前は festival-inventory などにし、地域は日本に近い場所を選びます。プランと料金表示を確認し、データベースのパスワードは自分で管理してください。

2. データベースの設定を入れる

左メニューの「SQL Editor」で新しいクエリを開き、setup.sqlの全文を貼り付けてRunを押します。これは専用の新しいプロジェクトで一度だけ実行します。成功すると3つのテーブルと2つの関数が作られます。数量は0から始まります。

3. 利用者を登録する

  1. Authentication → Users → Add user → Create new userで、使う人のメールアドレスとパスワードを設定します。パスワードは本人が設定・管理してください。
  2. 次のSQLのメールアドレスと表示名を実際の値に変更して、SQL Editorで実行します。
insert into public.festival_members (user_id, display_name)
select id, '運営メンバーの名前'
from auth.users where lower(email) = lower('member@example.com')
on conflict (user_id) do update
set display_name = excluded.display_name, active = true;

ユーザーを作るだけでは備品にはアクセスできません。このメンバー登録も必要です。利用者全員のSupabase管理アカウントは不要です。

4. config.jsに接続情報を設定する

Supabaseのプロジェクト設定で「Project URL」と「Publishable key」を確認し、config.jsの空欄に入れます。

window.FESTIVAL_CONFIG = {
  supabaseUrl: "https://プロジェクトID.supabase.co",
  supabasePublishableKey: "sb_publishable_から始まる公開用キー"
};

旧形式のanon keyも使えます。Secret key・service_role・データベースのパスワードはここに入れません。接続情報を変更しても再ビルドは不要です。

5. GitHubで公開する

  1. GitHubの新規リポジトリ作成画面から、文化祭サイトとは別のリポジトリを作ります。
  2. ZIPを展開し、このフォルダーの中身をアップロードします。index.htmlがリポジトリの一番上になるようにします。
  3. Settings → Pagesで、Sourceを「Deploy from a branch」、Branchを「main」、フォルダーを「/(root)」にしてSaveを押します。
  4. 表示された公開URLを開き、登録した利用者でログインします。

6. 実際の個数を登録する

場所・備品を追加し、各場所の「個数を設定」で初期個数を入れます。運んだあとは「移動を記録する」で両方の場所の個数が更新されます。別のスマホから同じ個数が表示されることも確認してください。

困ったとき

  • 「保存先の設定を待っています」：config.jsのURLと公開用キーを確認します。
  • 「メンバー未登録」：Authenticationのユーザーに加え、festival_membersの登録とactive=trueを確認します。
  • 「関数が見つからない」：setup.sqlが最後まで成功したか、接続しているプロジェクトが正しいか確認します。
  • 「ほかの人が更新しました」：最新の個数を見て、もう一度登録します。
  • パスワードを忘れた場合：運営管理者に連絡してください。
